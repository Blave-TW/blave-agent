# Shared Library (lib/)

The workspace has a shared library at `lib/`. Use it to avoid duplicating code across strategies.

**Always import these — never write them inline:**

Every `fetch_*` function takes `headers` as its auth argument. Build it once from the workspace `.env` — the keys are lowercase, and the header names are `api-key` / `secret-key` (not `X-API-KEY`, and there is no request signing):

```python
from dotenv import dotenv_values
env  = dotenv_values()   # run from the workspace root, or pass the .env path
hdrs = {'api-key': env.get('blave_api_key', ''), 'secret-key': env.get('blave_secret_key', '')}
```

`lib/data.py` — all data fetching (chunking + cache built-in):
- `fetch_db_kline(dataset, symbol, schema, start, end, headers)` → CME/NYMEX/ICE OHLCV + `instrument_id` column; datasets: `GLBX.MDP3` (CL, GC), `IFEU.IMPACT` (BRN); schemas: `ohlcv-1m` / `ohlcv-1h` / `ohlcv-1d`
- `settlement_signals_from_db(df, signal)` → returns `(signal, exec_at_close)`. For futures strategies using `fetch_db_kline`: call at the end of `compute_signals` and `return` the result directly. Forces `signal=0.0` on the last bar before each contract rollover, and marks those bars `exec_at_close=True` (executed at this-bar close, not next-bar open). Do NOT use `-1.0` for settlement — that opens a short position.
- `fetch_kline(symbol, interval, start, end, headers)` → OHLCV DataFrame (Open/High/Low/Close/Volume — Volume is real base-asset volume; individual bars may have `NaN` Volume when the source is missing it, so volume-based logic must handle NaN itself — `dropna`/`fillna`, never assume all-finite).
  - **Binance USDT-M perps only** — a contract listed elsewhere is simply absent, so a symbol that "works" is not proof it is the user's instrument.
  - All intervals (`1min`–`4min` included) reach back to the symbol's Binance um-futures listing date — the API backfills old months from Binance's official archive; a window before listing returns empty rows, not an error.
  - First deep sub-5min fetch pulls history month-by-month (30-day chunks server-side), so expect the cold run to take a while; it lands in the local monthly cache and is fast afterwards.
  - On the desktop build the environment sets `BLAVE_KLINE_SOURCE=binance` and the same bars are paged straight from Binance's public endpoint instead — same USDT-M market, same columns, same local cache, no key; nothing a strategy sees changes
- `fetch_kline_batch(symbols, interval, start, end, headers)` → `{symbol: OHLCV DataFrame}` for many Binance USDT-M perps in one call (20 symbols per request) — the Type C price fetcher for a crypto universe; never loop `fetch_kline` per symbol in parallel.
  - Keys are the normalized symbols (`'BTCUSDT'` even when `'BTC/USDT'` was passed); each frame is what `fetch_kline` returns and shares its monthly cache.
  - Some symbols still failing after the retry pass raises `lib.data.BatchIncomplete` (`.partial` / `.failed`) — a backtest or live tick must not continue on `.partial`.
  - On the desktop build (`BLAVE_KLINE_SOURCE=binance`) it pages each symbol from Binance, up to 4 side by side (sub-5-minute intervals one at a time).
- `fetch_bingx_kline(symbol, interval, start, end)` → OHLCV DataFrame for a BingX perpetual, straight from BingX's public API (no `headers` — no key needed). Use for contracts `fetch_kline` does not carry. `symbol` is the BingX **API** symbol, not the chart's display name: GOLD(XAU)-USDT is `NCCOGOLD2USD-USDT` — resolve it via `GET https://open-api.bingx.com/openApi/swap/v3/quote/contracts` (match `displayName`, use `symbol`). Intervals: `1min`/`3min`/`5min`/`15min`/`30min`/`1h`/`2h`/`4h`/`6h`/`8h`/`12h`/`1d`/`3d`/`1w`
- OHLC fetchers (`fetch_kline`, `fetch_db_kline`, `fetch_twfutures_ohlcv`, `fetch_twstock_price`) drop bars with impossible values (high<low, non-positive or NaN price) at read time and print the dropped timestamps — a printed `⚠️ dropped N bar(s)` warning means upstream data was corrupt, not a fetch failure; the cache keeps the raw bars
- **Alpha fetchers — quick reference** (there is no generic `fetch_alpha` / `get_alpha`; one function per alpha, every one → DataFrame with an `alpha` column; details per function follow):
  `fetch_holder_concentration(symbol, interval, start, end, headers)`
  `fetch_funding_rate(symbol, interval, start, end, headers, exchange='binance')`
  `fetch_taker_intensity(symbol, interval, start, end, headers, timeframe='24h')`
  `fetch_whale_hunter(symbol, interval, start, end, headers, timeframe='24h', score_type='score_oi')`
  `fetch_unusual_movement(symbol, interval, start, end, headers, timeframe='24h')`
  `fetch_squeeze_momentum(symbol, start, end, headers)`
  `fetch_liquidation(symbol, interval, start, end, headers, timeframe='24h')`
  `fetch_market_direction(interval, start, end, headers)`
  `fetch_capital_shortage(interval, start, end, headers)`
  `fetch_market_sentiment(symbol, interval, start, end, headers)`

- `fetch_holder_concentration(symbol, interval, start, end, headers)` → DataFrame with `alpha` column
- `fetch_funding_rate(symbol, interval, start, end, headers, exchange='binance')` → DataFrame with `alpha` (alpha = funding rate × 100). `exchange` picks whose perp funding is read: `binance` (default) / `okx` / `bingx` / `bybit`; symbol stays the Binance form (`BTCUSDT`) and the joined close is always the Binance perp
- `fetch_taker_intensity(symbol, interval, start, end, headers, timeframe='24h')` → DataFrame with `alpha`
- `fetch_whale_hunter(symbol, interval, start, end, headers, timeframe='24h', score_type='score_oi')` → DataFrame with `alpha`
- `fetch_unusual_movement(symbol, interval, start, end, headers, timeframe='24h')` → DataFrame with `alpha`
- `fetch_squeeze_momentum(symbol, start, end, headers)` → DataFrame with `alpha` (period fixed to 1d)
- `fetch_liquidation(symbol, interval, start, end, headers, timeframe='24h')` → DataFrame with `alpha`
- `fetch_liquidation_coin(symbol, headers)` → dict snapshot (not a DataFrame): one coin's USD liquidations across the six exchange feeds — `windows` 1/4/12/24 h rolling (total/long/short, `by_exchange`), `series.points` 24 hourly bars (last = current hour so far), `exchanges[]` (`listed`, price basis, coverage), `rank`, `detail_complete`. `windows['24']` is the same number as the exchange matrix; Σ `series.points` is a different (clock-hour) frame. `None` = symbol no feed lists; no local cache (server 5-min cache)
- `fetch_liquidation_exchanges(headers, hours=24, top_n=10)` → dict snapshot: the whole-market liquidation matrix behind `fetch_liquidation_coin` — `exchanges[]` per-venue totals with the basis columns (`price_basis`, `coverage`, `time_basis`), `coins[]` the top `top_n` by cross-venue total with their `by_exchange` split, `others` (with `coin_count`) so `coins[] + others` adds back to each venue's total, plus `total`, `window_*`, `covered_hours`.
  - Same rolling 5-min-aligned frame as that coin endpoint, so a coin's 24 h total matches on both.
  - `hours` 1–168, `top_n` 1–50 — outside that the API answers 400 (it does not clamp).
  - No local cache (server 5-min cache)
- `fetch_liquidation_map(symbol, headers)` → dict snapshot: one coin's 爆倉地圖 over 200 price buckets (`labels`, USDT) around the current `price`, two layers — `liquidation['24h']` `buy_liq[]` / `sell_liq[]` = Binance liquidations that HAPPENED in the last 24 h (USD, scaled to the whole market by a fixed 0.3 Binance share; `buy_liq` = shorts liquidated, `sell_liq` = longs), and `oi_value[]` / `cumsum[]` = a MODEL ESTIMATE of where open interest would be liquidated.
  - The estimate layer is not orders and not events — say so wherever it is shown. In a report use the `liq_map` brick (`references/reports.md`), which labels it.
  - `symbol` accepts `BTC` / `BTCUSDT`. Needs Blave data access; a snapshot of now — no history to backtest on, no local cache.

**Raw cross-exchange base data (dict snapshots, not DataFrames).**
Three datasets, each with a whole-market table and a per-coin endpoint.
They are cross-sections of *now*, not history to backtest on — for a signal series use the alpha fetchers above; open interest alone also has a backtestable series, `fetch_open_interest_history` (below).
Every one of them: no local cache; a coin no source collects → `None` on the coin fetchers (the API's 404); a `503` raises after the retry backoff and must never be read as zeros or an empty market.
Only coins that resolve to a CoinMarketCap crypto are listed; an API key sees every row (`full: true`), an anonymous caller 30. Granularity is 5-minute buckets, but the two table jobs are rebuilt on a schedule (≈ every 15 min, Gate / OKX land ≈ 10 min late) — never tell the user it updates every 5 minutes.
Field-by-field shapes are in each function's docstring.
- `fetch_long_short_ratio_table(headers)` / `fetch_long_short_ratio_coin(symbol, headers)` — 多空比 (`/long_short_ratio/get_table` / `get_coin`).
  - `fetch_long_short_ratio_coin` is capped at 200 calls/hour per API key (429) — never loop it over coins; one `fetch_long_short_ratio_table` call has every coin's latest value.
  - **10 sources**: Binance / OKX / Gate × (account, top account, top position) + Bybit account; read `sources[]`, never a hard-coded key list.
  - Values are longs ÷ shorts (long share = `r / (1 + r)`, computed by the caller); the coin endpoint adds a 7-day hourly `series` per source plus `latest` 5-min points and `price`.
  - **The three venues' "top trader" is three different populations** — Binance = top 20 % of users by margin balance, OKX = top 5 % of traders by open-position value, Gate has never published its rule — so `binance_top_account` vs `okx_top_account` is not a like-for-like comparison of levels; compare each source against its own history
- `fetch_open_interest_table(headers)` / `fetch_open_interest_coin(symbol, headers)` — 未平倉量, 5 venues (Binance / OKX / BingX / Bybit / Gate).
  - `fetch_open_interest_coin` is capped at 200 calls/hour per API key (429) — never loop it over coins; one `fetch_open_interest_table` call has every coin's latest value.
  - Basis: USDT-margined perps only, USD notional, one-sided (a venue that reports both sides is halved — `side_factor`), so venues add up directly even for 1000× contracts.
  - **`oi_total` / `oi_mcap` here are NOT the OI 失衡 indicator** (`/oi_imbalance/get_overview_data`, Binance + OKX + BingX only — no lib wrapper, it is what screener conditions and alerts hold thresholds on): different numbers, so a threshold tuned on one does not transfer.
  - Each window counts only the venues that have a baseline at its start (`windows.<w>.exchanges` names them), and a venue with less than 7 days of history (`full_7d: false`) is left out of the 7-day total and of `series.total`.
  - Endpoints: `/oi_imbalance/get_table` / `get_coin` — the PATH still carries the old "imbalance" name, the data does not
- `fetch_open_interest_history(symbol, interval, start, end, headers, exchange='binance')` → DataFrame with `alpha` (UTC index, bucket start) — **open interest history to backtest on**: one coin, ONE exchange (`binance` default / `bybit` / `gate`), `/oi_imbalance/get_history`; cached monthly like the alpha fetchers, unlike the snapshots above.
  - Use it whenever the user wants OI over time (a signal, a backtest, a chart longer than 7 days); use the table / coin snapshots above for "now" and the last 7 days across all five venues.
  - `alpha` is **one-sided OI in coins, not USD** (1000PEPE comes back as PEPE coins), the last reading of each bucket (a level, never summed); the last bucket keeps changing until it closes, as with klines (`1d` includes today's open bucket) — same basis as the Studio dashboard 未平倉量 card, and a different number from the table/coin USD totals and from OI 失衡.
  - USD OI = `alpha` × price per coin: on a multiplied contract `fetch_kline('1000PEPEUSDT', …)` close is per 1000 coins, so divide it first.
  - Interval min 5min (`1w` is a 400).
  - An unlisted or delisted coin raises HTTPError 404 (`<TOKEN> is not a collected symbol on <exchange>`) — an answer, not a transient; 503 is retried then raises
- `fetch_cme_cot(contract, start, end, headers)` → **CME Bitcoin / Ether futures positioning (CFTC Commitments of Traders, weekly)**, one row per report date (normally a Tuesday, a Monday when Tuesday is a US holiday; naive index), flat columns `tff_{dealer|asset_manager|leveraged_funds|other_reportables|nonreportable}_{long|short|spread|net|…_change}`, `legacy_{non_commercial|commercial|nonreportable}_…`, `open_interest(_change)`, `price` (Binance spot UTC close on the report date).
  - `contract`: `'btc_combined'` / `'eth_combined'` (standard + micro, in COINS — the usual choice; the series steps up the week micro joins, see `included`) or `'btc'` / `'micro_btc'` / `'eth'` / `'micro_eth'` (in CONTRACTS — 5 / 0.1 / 50 / 0.1 coins each).
  - `start=None` = only the last 365 days — pass `'2018-01-01'` for full history (BTC from 2018-04-10, ETH 2021-04-06).
  - Published on the Friday of the report date's week, 15:30 New York — a federal holiday Wed–Fri moves it to the next business day, and a government shutdown delays it by weeks (2018-12 → 2019-03, 2025-10 → 2026-01): in a strategy attach with `align_feed(bars, cot, 'cme_cot', INTERVAL, bar_tz='UTC')`, which knows those dates (`FEED_TIMING['cme_cot']`) — never `join` by date (three days of look-ahead at least, weeks in a shutdown).
  - `*_change` is CFTC's own figure (CFTC skips weeks; never diff rows).
  - **Leveraged funds net short is not a bearish bet by itself** — CFTC counts only same-market offsets as spreading, so a basis trade (long spot / ETF, short CME futures) shows up as a plain short (CFTC TFF Explanatory Notes: leveraged-fund strategies "may involve taking outright positions or arbitrage within and across markets"); say so whenever you report it.
  - Any figure shown carries `df.attrs['source']` (CFTC attribution).
  - No local cache
- `fetch_cvd_table(headers)` / `fetch_cvd_coin(symbol, headers)` — 主動買賣淨額 / CVD (`/taker_intensity/get_cvd_table` / `get_cvd_coin`), 3 venues (Binance from the 5-min kline's taker-buy quote volume, OKX, Gate).
  - **Perps only — no spot, and not trade-by-trade**; each venue's own reported USD turnover is used, never volume × a borrowed price.
  - Windows are rolling and end at the last closed bar; a venue more than an hour behind answers null windows + `stale: true` and drops out of the totals rather than under-reporting the window.
  - Same `full_7d` rule as OI (OKX only keeps 5 days).
  - The coin endpoint's `series` gives hourly `net` and cumulative `cvd` (`cvd[0] = 0`)

- `fetch_market_direction(interval, start, end, headers)` → DataFrame with `alpha` (no symbol)
- `fetch_capital_shortage(interval, start, end, headers)` → DataFrame with `alpha` (no symbol)
- `fetch_market_sentiment(symbol, interval, start, end, headers)` → DataFrame with `alpha`
- `fetch_top_trader_exposure(interval, start, end, headers)` → DataFrame with `alpha` (market-wide, no symbol; a raw ratio, **not** a z-score — see the coverage list below)

**Data coverage & scale — measured facts, do NOT probe the API first.**
When the user has not fixed a START (or you need the full history), request from the dataset's start date below — never widen a START the user gave; the actual first bar for a given symbol is simply `df.index[0]` (= max(dataset start, listing date) — e.g. DOGEUSDT 2020-07-10, SOLUSDT 2020-09-14, 1000PEPEUSDT 2023-05-05; HC for late listings can start months after listing).
Every alpha below is on a z-score-like scale (mean≈0, std≈1) unless stated, so the scale is the same for every symbol.
Measured 2026-08-22 on BTC/ETH/DOGE/SOL/1000PEPE, `1d` and `1h` both available (`whale_hunter` and `liquidation` re-measured 2026-09):
- `fetch_kline` — from **2020-01-01** (or listing); price, not a z-score. The `1d` series includes today's still-open bar (not closed until 00:00 UTC). Tokenized US equities / ETFs (`AAPLUSDT`, `NVDAUSDT`, `TSLAUSDT`, `SPYUSDT`, `QQQUSDT`… — use the `USDT` form like every other symbol) are Binance perps listed **from 2026-01 onward** (TSLA 2026-01-28, NVDA/META/GOOGL 2026-03-26, AAPL/SPY/QQQ 2026-04-06), so any window before their listing is empty — that is pre-listing, not "no history". Their per-symbol alphas start later still (NVDA holder_concentration 2026-04-01) — read `df.index[0]`.
- `fetch_holder_concentration` — from **2021-05-11** (BTC/ETH; DOGE/SOL 2021-05-28; 1000PEPE 2024-02-27); mean≈0, std≈1.2, p1≈−2.4, p99≈+3, extremes ≈−5…+11 (`1h` tails fatter). It is a 30-day rolling z-score of log(long/short account ratio): a value near 0 means the ratio sits at its 30-day mean — a normal reading, not missing data. A 1σ→0 move within one day happens whenever the ratio moves ~25–30%; do not report it as an anomaly.
- `fetch_taker_intensity` — from **2020-01-01** (or listing); std≈1.1, p1≈−3.4, p99≈+2.5…3, extremes ≈−10…+11.
- `fetch_whale_hunter` — from **2021-12-01** (or listing month); std≈1.05–1.1, p1≈−2.7, p99≈+3…4. **The tail scale is set by `timeframe`:** on the default `timeframe='24h'` extremes reach only ≈±10, while `timeframe='1h'` reaches ≈±20…30. Read the threshold off the timeframe you actually fetch — a ±25 level copied from the `1h` scale onto a default `24h` fetch never triggers at all.
- `fetch_liquidation` — from **2023-01-01** (BTC/ETH; other symbols start later — read `df.index[0]`). Re-measured 2026-09 on 1h bars over 2024-09…2026-09: mean negative and **more negative the smaller the coin** (BTC −0.09, DOGE −0.35 on the default `timeframe='24h'`), std≈1.15–1.28, and the distribution is **asymmetric** — p1≈−3.8…−4.1 but p99≈+2.8…+3.3, so a symmetric threshold is not symmetric in practice. Extremes are not quotable: the largest values come from single 5-minute buckets that look like bad data.
- `fetch_funding_rate` — **only from 2025-09-30** (say so before proposing a long backtest; `exchange='bybit'` starts later still — read `df.index[0]`); NOT a z-score: funding rate × 100, mean≈0.002–0.003, std≈0.005–0.02, extremes ≈−0.3…+0.07.
- `fetch_open_interest_history` — 5-minute resolution from **2021-12-01** on `binance` (or the coin's listing), **2025-08-21** on `bybit`, **2026-03-28** on `gate`; currently listed contracts only. An earlier `start` is moved up to that day by the lib (the API itself answers 400 for a window starting before the exchange's history). A level in coins, not a z-score — a threshold on the raw level does not carry across years or coins; work on its changes.
- `fetch_market_sentiment` — from **2020-01-01** (values only become meaningful from ≈2020-01-31); `min_period` 5min.
- `fetch_top_trader_exposure` — from **2025-03-03**; NOT a z-score: the median, across top traders, of each trader's net notional position ÷ own assets, ×100 (positive = net long), so ±1 / ±2 style z-score thresholds do not apply. One market-wide series — every coin those traders hold, aggregated; no symbol dimension.
- Daily alphas end at the **last closed day (yesterday)** — that is not a lag, it is the last complete bar; joining onto today's open `1d` kline bar leaves that row's alpha NaN (a blind `ffill` would carry yesterday's value onto it). Hourly alphas and kline run to the current hour. Exception: `fetch_open_interest_history` `1d` includes today's still-open bucket, like the kline.
- Not yet measured (`unusual_movement`, `squeeze_momentum`, `market_direction`, `capital_shortage`): fetch from 2020-01-01 and read `df.index[0]`; one call answers the question.

**Data-depth discipline (why AGENTS.md makes this absolute):** how far back a dataset reaches is a platform fact that changes over time (sub-5min crypto klines were capped at 45 days, then extended to each symbol's listing date), and a remembered limit outlives the change: an agent that hit `only goes back 45 days` in the morning kept telling the user "1m cannot do two years" all afternoon — after the platform had already lifted the cap and the local lib no longer contained the check — because the rolling conversation memory, a note in the strategy file, and a skill doc that had not yet re-synced all still said so.
Skill docs re-sync once a day, so they can lag a platform change by up to a day; conversation memory never expires on its own.
So before asserting a depth limit, probe it live, once, narrowly:

```python
# a few days at the deep end of the range the user wants — one call, not a backtest
df = fetch_kline('BTCUSDT', '1min', '2024-01-01', '2024-01-03', headers)
print(len(df), df.index.min() if len(df) else 'empty')
# "does this symbol have history at all?" is NOT a probe — fetch from the dataset start (the lib chunks it); empty here means truly none
df = fetch_kline('AAPLUSDT', '1d', '2020-01-01', None, headers); print(df.index[0] if len(df) else 'no history')
```

Scope: history depth only.
Per-request window caps (twstock kbar 31 days, TXF per-schema ranges, sub-5min 30 days) are real and handled by the lib's chunking — never probe those.
An empty depth probe only proves "no bars in this window": a window before the symbol's listing returns empty with HTTP 200, not an error — never answer "does this symbol have history" from a fixed old window; use the dataset-start fetch above.
For sources that backfill progressively (twstock minute lines seed ~30 recent days on first query and deepen afterwards — see `references/twstock.md`) report the documented coverage, not "no data".
Then fix the stale note in the strategy file so the wrong limit does not get re-read next turn.

**Taiwan stock price — raw vs adjusted (critical distinction):**
- `fetch_twstock_price(sid, start, end, headers)` → Open/High/Low/Close/Volume, **actual market prices**. Use when the user asks to plot or view a stock's trend — matches what they see on broker apps.
- **Both daily fetchers need no Blave key.**
  - On every machine the bars come from the **Blave CDN** first: Blave's daily copy of TWSE `afterTrading/MI_INDEX` and TPEx `afterTrading/dailyQuotes` (whole-market closing files, 2010-01-04 on, delisted stocks included), one parquet per stock at `download.blave.org/data/twstock/daily/v1/`, published ~17:55 Taipei; between 17:35 and then, the missing days come from the exchange (desktop) or the whole id from the Blave endpoint (cloud, or a desktop whose exchange tail failed). Then the Blave endpoint (no data access → straight through), then, on the desktop only, the stock's own exchange month by month — TWSE `exchangeReport/STOCK_DAY` (2010-01-04 on) or TPEx `afterTrading/tradingStock` (back to the 1990s) — then a third-party free source (the last resort, raw prices only).
  - `adjust` uses the exchanges' own price-continuity tables — 除權息 (TWSE `TWT49U` / TPEx `exDailyQ`), 減資 (`TWTAUU` / `revivt`), 變更面額 (`TWTB8U` / `pvChgRslt`), ETF 分割・反分割 (`TWTCAU` / `etfSplitRslt`, `etfRvsRslt`): factor = 前收盤價 ÷ 參考價 from the event date on. The Blave adjusted series uses the same exchange events, so the two agree except on bars no exchange event reaches (mostly pre-2010 and 興櫃-era history, where Blave falls back to its dividend formula) and on an event day before 17:55, when Blave already carries the morning-listed event.
  - **Attribution line for any report or reply that cites these bars, CDN or exchange path alike: `資料來源:臺灣證券交易所、證券櫃檯買賣中心(政府資料開放授權)`** (en: `Source: Taiwan Stock Exchange, Taipei Exchange (Open Government Data License)`) — the data is the exchanges' open data and naming them is the licence condition.
  - Exchange-path limits (only when the CDN is not serving — a ⚠️ line says so): one request every 3 s to twse.com.tw, one per second to TPEx and the third-party source (a cold 2010→today backfill of a listed stock is ~200 requests ≈ 10 min; each month is cached as it arrives and the current month is re-fetched only after the next 17:35 final), TPEx volume rounded to the thousand (成交仟股), TWSE nothing before 2010-01-04, a stock that moved from TPEx to TWSE only has its post-transfer months there.
  - Chains: default (`cdn`, every machine) CDN → Blave → exchange → third-party free source, the last two on the desktop only; `public` exchange → third-party free source → Blave; `blave` Blave only. **免費來源只在用戶自己的電腦上抓** — a cloud machine's chain is CDN → Blave (the CDN is Blave's own `download.blave.org`): no exchange tail, no exchange probe, the holiday table tells a late CDN from a closed day; `BLAVE_TWSTOCK_DAILY_SOURCE=cdn|public|blave` overrides either way.
  - `df.attrs['source']` says who supplied the numbers (`TWSE` / `TPEx` / `Blave`, or the third-party source's own tag on the last-resort path), `df.attrs['via'] == 'Blave CDN'` when the CDN served them; a fallback prints a ⚠️ line.
  - The `*_batch` variants: CDN first too, for every id it lists from 2010-01-04 on (per stock up to 40 ids, the whole-market year files above that); one Blave batch for the rest — ids the CDN does not list (興櫃, a newer listing), a start before 2010-01-04, a CDN that is down, ids whose CDN frame is short of the latest final. Without Blave access the desktop sends those through the exchange chain and a cloud machine gets the access error; still-missing ids → `BatchIncomplete`. A Type C strategy does not catch `BatchIncomplete` and never goes on with `.partial`: the backtest fails, and a live tick sends a fetch_error alert and retries on its own. An id no source has (delisted, a wrong code) is simply absent from the dict — skip it with `.get(sid)`. A start earlier than the cache is back-filled 50 ids per batch request, never one request per id. While the CDN is behind the latest 17:35 final, single stocks and per-stock batches fill the days from the exchange; a frame still short (single or batch) carries `df.attrs['asof']` + a ⚠️ line, and a live tick gets `FeedNotPublished` (it waits, never trades on the older day). `fetch_twstock_ohlcv(…, '1d')` is unchanged (Blave).

**Macro economic calendar — the only source for macro events and their numbers:**
- `fetch_economic_calendar(headers, start=None, end=None, countries=None, max_priority=None, limit=None, lang='zh')` → DataFrame, one row per event, sorted by event time. Columns: `datetime` (Taipei time; events with no published time get 00:00), `date`, `time` (`'HH:MM'` Taipei, may be `None`), `country` (ISO-2) / `country_name` (Chinese), `subject` (indicator name) / `subject_title` (period, e.g. `'<7月>'`, `'<2季>'`), `predict` (market consensus), `last` (prior), `real` (actual; `None` until released), `unit`, `priority`.

  **Macro facts discipline (why AGENTS.md makes this absolute):** a generic web search lands on calendar-aggregator content farms whose tables are themselves wrong, and whatever the page does not cover gets filled in from training data — measured on a real digest, that produced a wrong prior for China's PMI (49.5 vs the actual 50.3, a published fact with one right answer), a prior belonging to a different indicator entirely, and a Q2 GDP consensus off by 0.7pp.
  Time-sensitive facts the calendar does not cover are worse: memory silently overrides what was just read (a weekly digest called the FOMC presser Powell's months after Warsh replaced him, and a later run wrote 「鮑威爾（Kevin Warsh）」 while the fetched page said Warsh).
  Web search is blocked outright on some machines — every such failure is exactly the moment the tempting move is to fill the gap from training data.
  Never present an unverified name or number as fact.
- **`priority` runs 1 → 3 with 1 the MOST important** (1 = non-farm payrolls, rate decisions; 3 = rig counts, used-car indices). `max_priority` keeps only `priority <=` it, so "just the big events" is `max_priority=1`, not 3. Getting this backwards silently returns ~979 rows of noise instead of the 85 that matter.
- Other filters: `start`/`end` are `'YYYY-MM-DD'` Taipei dates (inclusive); `countries` is a list of ISO-2 codes, e.g. `['US', 'CN', 'TW']`; `limit` truncates after sorting; `lang` (`'zh'` default / `'en'`) picks the display language for indicator and country names — the server only swaps names it has in its lookup table, so `'en'` returns a zh/en mix. Unfiltered the feed is ~1,400 rows — always filter.
- **Coverage is a rolling ~5-week window (roughly the past month plus the next few weeks), not a history archive.** A range outside it returns an empty DataFrame rather than an error — do not read that as "no events scheduled". For anything older, there is no endpoint; say so instead of substituting a remembered figure — except a past event's date (an FOMC meeting), which comes from the official source's own page, cited.
- **Never answer a macro-event question from a web search or from memory.** Search results land on calendar-aggregator content farms whose own tables are wrong (measured: one listed a published actual as the consensus), and any field the page misses gets filled in from training data — that is how a digest ended up with China's manufacturing PMI prior at 49.5 when the published figure was 50.3, and a Q2 GDP consensus 0.7pp off. If this call cannot answer it, say so rather than substituting a number.
- **Data history ranges:** the start dates measured for the crypto alphas are listed above (the `Measured …` list) and are a snapshot — this file only changes when the workspace is updated, so a date here can be stale. Before telling the user a dataset does not reach back far enough, probe it once (*Data-depth discipline* above); an endpoint with no date listed → fetch from its dataset start and read `df.index[0]`.

`lib/execute.py` — all order execution logic (state management + algo orders):

- `state.json` schema: `{"position": float, "symbol": str}` — `position` is the current signal value (positive=long, negative=short, 0=flat); all deployment config (exchange, asset_spec) lives in `portfolio_config.json`, not in state. A Taiwan-stock target also carries `raw_closes` / `raw_close_dates` (and `raw_closes_est`, `raw_close_want`), written by the live tick after the position is saved (`lib/runner.tw_carry_closes` / `tw_fetch_closes`): the unadjusted close the portfolio page sizes whole lots with, taken on the tick the target changed and carried while it holds — leave them alone, nothing trades on them
- `from lib.execute import run_twap` — TWAP execution engine (exchange-agnostic). The reconciler's execution dispatch (below) drives it automatically; call it directly only for standalone Type B tooling.
  - `run_twap(symbol, side, total_qty, duration_min, n_slices, place_slice_fn, twap_key, signal_price=None, send_telegram_fn=None, stop_event=None, notify_slices=True)`
  - `place_slice_fn(symbol, side, qty) → {'fill_price': float, 'fill_qty': float}` — raise on failure; 3 consecutive slice failures abort the run
  - `stop_event` (threading.Event): once set, remaining slices are skipped and the summary carries `aborted=True`; `notify_slices=False` silences per-slice Telegrams (start/errors/summary still send)
  - `twap_key`: **symbol+direction** key like `'btcusdt_long'` / `'btcusdt_short'` — NOT a strategy name. Reconciler nets orders per symbol, so there is no single strategy name at execution time.
  - Logs every slice + summary to `manager/twap/{twap_key}.jsonl` (under `manager/`, never `strategies/`)
  - `signal_price` (optional): price at signal time — used to compute `slippage_bps` per slice and in the summary
- `from lib.execute import load_twap_log` — `load_twap_log(twap_key)` returns `(slices, summaries)` from `manager/twap/{twap_key}.jsonl`; use to analyze how TWAP parameters (duration, n_slices) affect execution quality vs strategy signal price

**Execution styles (下單方式) — BUILT IN, do not hand-wire TWAP into the reconciler anymore.** ONE style for the whole portfolio: `portfolio_config.json["execution_default"]` holds a single spec and every order of every symbol uses it (`reconcile()` nets strategies per symbol into one order, so a per-strategy style had no clean meaning). The reconciler template routes every order through `lib.execute.dispatch_order`, which resolves the spec (`resolve_execution` → `portfolio_execution`) and executes. No setting = market.
  - Specs: `{"type": "market"}` | `{"type": "twap", "duration_min": 1–1440}` | `{"type": "chase"}` | `{"type": "custom", "module": "<name>"}`
  - The web 下單設定 and the desktop app (自動下單 › 設定 › 下單方式) write it themselves via the `execution` command — when the user asks in chat, point them at that control. If they can't use it, set `execution_default` in `portfolio_config.json` directly; never edit the legacy `execution` map (the runtime rewrites it from `execution_default` on every save).
  - **Gate:** if the config has no `execution_fanned_from`, either the runtime is too old or the order style has not been saved since the update. Do not edit `execution_default` then. Ask the user to change it in the web or desktop settings.
  - `portfolio_config.json["execution"]` (strategy → spec) is now a compatibility copy the runtime writes, fanned out to every member, for workspaces older than the global setting. It is read only when `execution_default` is absent (a config never saved since): then the members with amount > 0 weigh in with their amount behind their own spec (no entry = market), the heaviest spec wins, a tie is market.
  - TWAP sizing is automatic: ~1 slice/minute, every slice ≥ $20; orders too small to slice fall back to a single market order. Slices are market orders through `lib/venue_wiring` — HALT, audit and broker attribution all apply.
  - **Chase (限價追價)**: post-only limit at our own side's best price, cancel-replace as the BBO moves, 45 s window, remainder then goes market — better average price than a straight market order, still guaranteed to converge. Zero user parameters. Requires the venue lib's limit layer (`references/exchange-connect.md` rule 6); a venue without it degrades to market, loudly.
  - TWAP/chase/custom run in a background thread: the reconcile loop keeps serving other symbols; repeat legs for an in-flight symbol are deferred (returned `False`); a mid-flight signal flip stops the execution before its next slice (chase also cancels its resting order) and the residual re-reconciles; a pause (`state/HALT`) or restart stop cancels chase's resting order at once (checked every 0.05 s while it rests), and any fill before the cancel lands is booked; completion touches `state/execution/kick` to trigger an immediate round and appends the fill summary to `manager/orders.jsonl`.
  - An unusable spec (missing module, bad duration) does NOT strand the position: it places a market order and tells the user via Telegram, every occurrence.
  - Auto-wired official venues only — Taiwan brokers (sinopac/president/capital) keep their hand-wired signed-diff reconcilers and never enter this path: their orders are always market, whatever the portfolio setting says (the web and desktop controls say so). Rows sized in lots or shares (`asset_specs` type `futures_contracts` / `shares`) are a single market order on every venue too.

**Custom executors — "write my own execution style".** When the user wants an execution shape the standard options don't cover (front-loaded slicing, randomized intervals, price-reactive pacing), write `manager/executors/<name>.py` (name: `[a-z0-9_]{1,64}`) exporting:
  ```python
  def execute(symbol, side, total_usd, ctx):
      # side: 'buy' | 'sell'; total_usd: positive USD to execute
      remaining = total_usd
      while remaining > 20 and not ctx.stop_requested():
          fill = ctx.place_slice(min(remaining, total_usd / 10))
          remaining -= fill["fill_qty"]          # fill_qty is USD
          if not ctx.sleep(60):                  # False = stop requested
              return
  ```
  then set `"execution_default": {"type": "custom", "module": "<name>"}` in `portfolio_config.json` — it applies to every order of the portfolio.
  - **Gate:** no `execution_fanned_from` in the config means the runtime is too old, or the order style has not been saved since the update. Do not set it then. Ask the user to save any order style once in the web or desktop settings; if the field is still missing after that, the machine needs a runtime update.
  - `ctx.place_slice(usd)` — one market slice of the order's own direction, returns `{'fill_price', 'fill_qty'}` (fill_qty in USD); raises on failure. `ctx.sleep(s)` — interruptible, returns False when the platform wants out (signal flip / HALT / overdue): **return promptly then** — a custom style shapes HOW the target is reached, never whether. `ctx.stop_requested()`, `ctx.mark_price()`, `ctx.notify(msg)`.
  - Everything still goes through the venue wiring: HALT, audit log, attribution, minimums. There is no way (and no need) to place raw orders from an executor.
  - Partial fills are fine — the reconciler re-diffs whatever is left after the executor returns. Do not loop forever "to be safe"; executions are expected to end (24 h hard deadline, then the platform requests stop and warns the user).
  - Keep executors small and boring; test the shape with a dry run of the math in `tmp/` first. Never write TWAP/execution logs under `strategies/`.

`lib/param_scan.py`:
- `from lib.param_scan import nice_grid, nice_step` — **build every scan axis with this.**
  - `nice_grid(lo, hi, n=15, current=<file constant>, integer=False)` → cells are `current + k*step` with step = `(hi-lo)/(n-1)` rounded to the nearest `{1, 2, 2.5, 5}×10^k`, covering `[lo, hi]` (ends rounded outward, at most one extra cell each side; `current` always covered).
  - The default `n=15` gives ≈ 11–21 cells after rounding — keep it: two such axes are 100–400 combos, ≤ 10 s for any strategy (scan time is linear in combos × bars; a 40×40 grid on two years of 5-min bars takes ~45 s), a finer step has no trading meaning, and the 3×3 neighbourhood mean degenerates into a single-cell pick when neighbours differ by noise only.
  - Rule: **range from the distribution (p5–p95) or the current value ± a span; cells must be integers or multiples of 1/2/2.5/5; the strategy's current value must be a cell.**
  - Why: the 參數掃描 tab (web and desktop) locates `current` on the axis to mark "you are here" — a percentile linspace (`0.065, 0.543, 1.022…`) never contains the file's constant, so the tab shows 「不在掃描範圍」 and cannot highlight the current cell.
  - `integer=True` for bar counts (SMA period, hold bars): step ≥ 1, int cells.
  - An axis longer than 40 is coarsened (next nice step), never truncated.
  - `step=` overrides the step (still anchored on `current`).
- `from lib.param_scan import percentile_thresholds` — momentum threshold pair: `percentile_thresholds(series, n_parts=17, current=(s.ENTRY_TH, s.EXIT_TH))` → `(entry_vals, exit_vals)` on one nice step across p5–p95 (default 17 cells across the whole span → each half ≈ 9 cells, ~100 combos), entry covering the upper half, exit the lower half, each anchored on its current constant (**always pass `current=`**; omitted → both anchored at 0). Prints the distribution and both axes.
- `from lib.param_scan import scan_grid` — run 2D param scan, returns Sharpe grid. Supports all strategy types:
  - Cells whose params never produce a trade are left NaN (excluded) — a do-nothing cell's Sharpe 0.0 would otherwise win the plateau in a losing period. If `find_plateau` raises "every grid cell is NaN", no combo traded: widen the scan ranges toward the indicator's actual value range.
  - `row_param`/`col_param`: kwarg names forwarded to `compute_signals_fn` (default `'entry_th'`/`'exit_th'`)
  - `warmup`: leading bars to skip from PnL (rolling window warm-up); `compute_signals_fn` receives the FULL df for accurate rolling, PnL computed on `df.iloc[warmup:]`
  - `valid_fn`: `(row_val, col_val) → bool` to skip invalid combos (default: `row > col`; for SMA use `lambda f, sl: f < sl`)
  - If `compute_signals_fn` returns a tuple `(signal, settle)`, `settle` is automatically used as `exec_shifted`
  - **All strategy types use the same `scan_grid` call** — see `examples/btc_sma_cross/scan.py` for the canonical SMA-scan pattern and `examples/btc_ti_5min/scan.py` for the threshold-scan pattern
- `from lib.param_scan import find_plateau, write_scan, plot_heatmap` — plateau detection, scan.json, heatmap chart
  - `find_plateau` returns 5 values: `best_idx, nbr_mean, best_row, best_col, best_sharpe` — use `best_row`, `best_col`, `best_sharpe` directly; `nbr_mean` is a **2D array** (do NOT format it as a scalar). **Keep `nbr_mean` — `write_scan` needs it.**
  - Canonical usage: `best_idx, nbr_mean, best_row, best_col, best_sharpe = find_plateau(grid, ROW_VALS, COL_VALS)`
  - `from lib.param_scan import on_edge, extend_axis` — **plateau on a grid border → extend that side once and rescan.**
    - `on_edge(best_idx, grid.shape)` → list of `(axis, side)` (`axis` 0 = rows / 1 = cols, `side` `'lo'` / `'hi'`; empty when interior, two entries at a corner).
    - `extend_axis(vals, side, k=5, floor=None)` → the same axis with `k` cells added beyond that end at the axis's own step (int axis stays int; clipped so the axis never exceeds 40 — at 40 it comes back unchanged; `floor=1` for bar counts so a `'lo'` extension never yields a 0/negative window).
    - A border plateau was measured on a truncated neighbourhood, so after `find_plateau`: `for axis, side in on_edge(best_idx, grid.shape)` → `extend_axis` the matching axis → run `scan_grid → find_plateau` again on the extended axes (a plain rescan is simpler than merging grids) → `write_scan` with the extended axes.
    - **Extend once only** — the rescan is part of the same scan and the same iteration under the Iteration Brakes; if the plateau is still on the border after that, report it as such and stop.
    - Pattern: `examples/btc_ti_5min/scan.py`, `examples/btc_sma_cross/scan.py`.
  - `write_scan(grid, row_vals, col_vals, nbr_mean, best_idx, output_dir, row_param, col_param, fee, start, end, current=None, window=1)` → writes `strategies/{strategy_name}/scan.json` (atomic). **Mandatory after every scan — the 參數掃描 tab (web and desktop) is built from this file; a scan that skips it is invisible on the web.** `row_param`/`col_param` are the strategy **constant names** (`'ENTRY_TH'`, not the `entry_th` kwarg — the web writes "把 ENTRY_TH 改成 …" from them); `current=(s.ENTRY_TH, s.EXIT_TH)` is what `strategy.py` holds right now (the web marks it; off-grid values are kept with `i/j = null`); `start` / `end` = **the backtest's own range, as recorded in `strategies/<name>/stats.json` (`start`, `end`)** — the 參數掃描 tab compares them (and `fee`) with the current backtest and marks the scan stale when `start` or `fee` differ, or when the backtest's `end` runs more than 30 days past the scan's (a scan written after the backtest may end later — fresher bars are not flagged). Type A: stats `start` is `s.START` verbatim, so pass `start=s.START`. Type C: stats `start` is the first bar the runner keeps after `WARMUP` (`price_df.iloc[WARMUP:]`), **not** `s.START` — pass `json.load(open('strategies/<name>/stats.json'))['start']`; `s.START` there flags every Type C scan stale the moment it lands. Recommended: scan the same bars the backtest saw — if the fetched data now runs past stats `end` (new bars since the backtest), cut it to that date (Type A `df = df.loc[:end]`) so the heatmap and the backtest describe the same period; a Type C data tuple that can't be cut cleanly can be scanned as fetched. No backtest yet → `end = df.index[-1].strftime('%Y-%m-%d')` and `start=s.START` (Type C: the first bar after `WARMUP`). It records both the global **peak** (nanargmax of `grid`) and the **plateau** (`best_idx`, Sharpe = neighbourhood mean) — report both, recommend the plateau. **Each axis is capped at 40 values** (api limit — `write_scan` raises past it; a bigger grid would upload nothing and leave the web tab blank), so keep scans within 40×40 via a coarser step or narrower range. An all-NaN grid never yields a scan.json (`find_plateau` raises first) — widen the ranges and rescan rather than writing anything by hand.
  - `plot_heatmap` `output_path` is **required** — always pass `output_path='strategies/{strategy_name}/heatmap.png'`, never `/tmp/`
  - `plot_heatmap` **auto-sends the heatmap to Telegram** (via `send_photo`) — you do NOT need a manual `send_photo` after it. Pass `send_telegram=False` only if you explicitly want to suppress it.
- `from lib.analysis import precise_pnl, compute_stats` — available if you need a custom loop (rare). `compute_stats(pf_ret, index)` → `(sharpe, sortino, omega, mdd, ann_ret)`, the numbers `stats.json` carries: Sharpe = mean / std(ddof=1) × √ppy; Sortino = mean / downside deviation × √ppy where downside deviation = `sqrt(mean(min(r, 0)²))` over **all** bars (MAR 0 — the textbook / empyrical definition, comparable with QuantStats and vectorbt; before desktop 0.1.20 the lib used the std of the losing bars only, so a Sortino stored in an older strategy version is not comparable with a new one); no volatility / no losing bar → 0.0, never inf

**Parameter scan workflow** — fixed order, one `scan.py` in the strategy folder: `scan_grid → find_plateau → (on_edge → extend_axis → scan_grid → find_plateau, once) → write_scan → plot_heatmap`.
Grid-size principles (Pardo's plateau-search practice / industry convention): (a) **10–20 values per axis** — `nice_grid` / `percentile_thresholds` defaults do this (100–400 combos; ≤ 10 s when `compute_signals` is vectorized — a per-bar Python loop costs ~0.5 s per cell on 390k 5-min bars; a two-sided threshold strategy built on `lib.strategy.threshold_position` scans each side with the other side pushed out of range (±1e9), which the lib turns into the vectorized one-sided path; `references/strategy-code.md` › *Scanning four thresholds*);
(b) **the step must mean something in trading terms** (whole bars for windows, a threshold move a trader would actually notice) — a finer step only makes neighbouring cells differ by noise and the plateau's neighbourhood mean collapse into a single cell;
(c) **coarse first, then fine** — if the plateau needs resolving, a second scan zooms into its neighbourhood with the same rules rather than starting fine.
40 per axis stays the hard cap (api limit).
1. Run `scan.py`: pick the ranges — look at the distribution first (p5–p95, or the current constant ± a span), then build the axes with `nice_grid` / `percentile_thresholds` at their default sizes, **anchored on the constants now in `strategy.py`** (cells = integers or multiples of 1/2/2.5/5, current value on the grid — otherwise the web tab says 「不在掃描範圍」 and cannot mark the current cell; see `references/strategy-code.md`), `scan_grid`, `find_plateau`;
   - **if `on_edge(best_idx, grid.shape)` is non-empty, `extend_axis` that side 5 cells and rerun `scan_grid → find_plateau` once** (same iteration; never a second extension);
   - then **`write_scan`** (pass the same `current=` and the axes actually scanned), `plot_heatmap`.
   - Three or more constants → pairwise coordinate descent, max two rounds, one `scan.json` (`references/strategy-code.md` › *Scanning three or more parameters*; example `examples/tw2317_broker_zscore/scan.py`).
   - One real constant only → the same workflow, and still `write_scan`, through a **one-cell second axis** — the same shape as *Single-constant walk-forward* below (`lib/walk_forward.py`): `row_vals = nice_grid(…, current=s.X, integer=…)`, `col_vals=[0]`; `scan_grid(df, lambda df, x, _none=0: s.compute_signals(df, x=x), row_vals, [0], row_param='x', col_param='_none', fee=fee_of(s), warmup=s.WARMUP, valid_fn=lambda r, c: True)` (the lambda swallows the unused kwarg; `valid_fn` is required — the Type A default `row > col` would skip every row value ≤ 0); `find_plateau` / `on_edge` / `extend_axis` work on the N×1 grid as they are (the neighbourhood is the three cells along the real axis, `j` is always 0, only the row axis can sit on a border); `write_scan(…, row_param='X', col_param='_', current=(s.X, 0))`. The 參數掃描 tab (web and desktop) reads `col_param '_'` with a one-cell `col_vals` as "no second axis" and draws one column; `plot_heatmap(…, col_label='_')` still gives the PNG. `'_'` + `[0]` is the only sanctioned second axis — never pad it with a fake range, and never scan `FEE` / `SYMBOL` / `INTERVAL` as a stand-in partner.
   - Report BOTH the peak (highest single cell) and the plateau (best neighbourhood mean) with their Sharpes, and recommend the plateau — a lone spike is the overfit cell.
   - When you tell the user where to look, it is the 「參數掃描」 tab (Parameter scan) — the heatmap and the full grid are drawn there from `scan.json`, on web and desktop alike; never send them to the 回測分頁 for a scan result.
2. **Update the params directly in the existing `strategy.py`** — do NOT create a new strategy folder
3. Run backtest in the same `strategy.py` to verify — `BLAVE_MODE=backtest python3 strategies/<name>/strategy.py` when the strategy is in the order settings (`amounts` key in `manager/portfolio_config.json`, amount 0 included), otherwise the run is a quiet live tick (`references/deployment.md` › *Live vs Backtest*)
Never create a duplicate strategy folder just because you ran a scan.

The web workspace sends four fixed prompts (bilingual — the zh or en version depending on the user's UI language; recognise either); treat them exactly as follows:
- **Scan** — zh「請掃描策略 {name} 的參數（lib.param_scan…」/ en「Please scan the parameters of strategy {name} …」 → run step 1 above on the strategy's two main constants and reply with the peak and the plateau (param values + Sharpe).
  - This is explicit permission for **one** scan and counts as **one** iteration under the Iteration Brakes — do NOT go on to edit `strategy.py` or re-run the backtest; the user picks on the web.
  - **Do NOT run MCPT on a scan** — neither per cell nor on the plateau: a scan is dozens to hundreds of backtests and MCPT on top would make it unusably slow (`scan_grid` never calls it by design).
  - The p-value comes from the backtest that follows the adopt step.
- **Adopt** — 「請把策略 {name} 的參數改成 A=…、B=…(穩健參數),重跑回測 … 不用再確認」(en equivalent ends the same way: no further confirmation) → the user has already chosen: set the named constants in `strategies/X/strategy.py` to exactly those values, run the backtest once (with `BLAVE_MODE=backtest` if X is in the order settings — step 3 above), report the new stats. No confirmation question, no counter-proposal, no extra scan.
- **Rescan** — zh「請重新掃描策略 {name} 的參數（lib.param_scan…」/ en「Please rescan the parameters of strategy {name} …」 → same as **Scan**, but keep the two axes and the min–max ranges the prompt names (`nice_grid` over that span; one `on_edge` extension allowed) and scan the backtest's current period and fee (the prompt quotes them; `start` / `end` as in `write_scan` above). Same limits: one scan, no MCPT, no edits to `strategy.py`.
- **Walk-forward (樣本外驗證)** — zh「對策略 {name} 做 walk-forward 樣本外驗證:訓練窗 {lookback} 天、每 {step} 天重新最佳化 …」/ en「Please run a walk-forward out-of-sample validation on strategy {name}: training window {lookback} days, re-optimize every {step} days …」 → run `lib.walk_forward.run_walk_forward` on the strategy's two main constants with the `lookback` / `step` the prompt names, on the SAME axes a scan would use, and reply with the out-of-sample Sharpe, the in-sample average and the WFE.
  - `run_walk_forward` **is** the implementation of what that prompt describes — never hand-roll a per-run scan loop (n full scans instead of one), never run MCPT here (this tab shows no p-value), and never edit `strategy.py` afterwards: a walk-forward produces NO adoptable parameters, its result belongs to no single fixed pair.
  - One walk-forward = **one** iteration under the Iteration Brakes.

`lib/walk_forward.py`:
- `from lib.walk_forward import run_walk_forward, default_windows` — **walk-forward out-of-sample validation**: re-pick the parameters inside each training window, apply them to the test window that follows, stitch the test windows into one out-of-sample series. Writes `strategies/{name}/wf.json` (atomic) — the web 樣本外驗證 tab is built from this file, so a validation that skips it is invisible on the web. **Rolling only** (the training window slides forward one step per run); anchored windows are not offered.
- `run_walk_forward(data, compute_signals_fn, row_vals, col_vals, output_dir, row_param, col_param, fee=..., row_kw='entry_th', col_kw='exit_th', lookback_days=None, step_days=None, valid_fn=None, warmup=0, window=1, current=None)` — `data` / `compute_signals_fn` / `valid_fn` / `warmup` are exactly `scan_grid`'s (Type A **and** Type C, `exec_at_close` and the TXF settlement mask travel the same path);
  - `row_param` / `col_param` are the strategy **constant** names as in `write_scan` (`'ENTRY_TH'` — the web compares them with the code to tell a stale result) while `row_kw` / `col_kw` are the `compute_signals` kwarg names;
  - `current=(s.ENTRY_TH, s.EXIT_TH)` is what the file holds now.
  - Axes come from `nice_grid` / `percentile_thresholds` exactly as for a scan and are **fixed for the whole validation** — no per-run `on_edge` / `extend_axis`, every run must land on the same lattice or the drift grid has no axis to plot against.
  - Max 40 per axis (api cap).
- `default_windows(total_days)` → `(lookback_days, step_days)`, three tiers: **1095 / 30** (three-year training window, re-optimised monthly) when the history is ≥ 1185 days; **365 / 30** at 455–1184 days (so a mid-length history never gets a window shorter than a year from the ratio formula); shorter histories fall back to `step = max(30, floor(total/12))`, `lookback = 4 × step` (≈ 8 runs; **floor, never round** — at 730 days `round` gives 61 → only 7 runs).
  - The step stays 30 on every tier: the run count only sets how often the pick is redone; the out-of-sample span is total days minus the training window.
  - Pass the user's numbers when the prompt names them; omit both to take this default.
  - Run count is bounded at 1000 (api cap), not a workload concern — 44 runs (365 / 30) on 4.7 years of hourly BTC took under two minutes end to end.
- **Single-constant walk-forward** (a strategy with ONE tunable constant): the grid is 2-D by contract, so run it 1-D through a one-cell second axis — `row_vals = nice_grid(…, current=s.X, integer=…)`, `row_param='X'`, `row_kw='x'`, `col_vals=[0]`, `col_param='_'`, `col_kw='_none'`, `compute_signals_fn=lambda df, x, _none=0: s.compute_signals(df, x=x)` (swallow the unused kwarg), `valid_fn=lambda r, c: True`, `current=(s.X, 0)`.
  - The web reads `col_param '_'` as "no second axis" and draws a one-column drift grid — the same convention as the single-constant parameter scan (*Parameter scan workflow* step 1 above).
  - Never pad the second axis with a fake range.
  - Verified end to end (lib → api → web) 2026-09-11.
- **Refusals** (both verified to be needed on a real machine): (1) 「把樣本外驗證選中的參數套進策略」→ 「樣本外驗證不產生可採用的參數——它的成績來自每輪重選,不屬於任何一組;要換參數請走參數掃描的穩健點。」 then stop, no edit, no rerun. (2) 「改用 anchored」→ 「這裡只提供 rolling(訓練窗跟著往前滑);anchored 不提供。」 then run rolling, or stop if declined. Do NOT implement anchored by editing `lib/walk_forward.py` — it is read-only (AGENTS.md › Shared Library; the resident runtime refuses the edit tools on it), and `wf.json` has no field to mark an anchored run, so the web would display it as rolling.
- **Cost**: two passes, together about 1.2 × one parameter scan. Pass 1 computes each combo's signals ONCE on the full history and prices every run's training slice from that single pass (a runs × rows × cols Sharpe grid); pass 2 recomputes only the run winners (≤ n_runs combos, usually fewer). No 400-combo × full-history position matrix is ever held — that would not fit a 2C/4GB Starter.
- **Three semantics that are contract, not implementation detail** (also in the module docstring):
  1. **Picking uses the neighbourhood mean; reporting uses the cell itself.** Each run picks with `find_plateau` (same 3×3 rule as the scan), but the reported `train_sharpe` — and therefore `is_stats['Sharpe Ratio']`, the WFE denominator — is the picked cell's OWN Sharpe. A neighbourhood mean is structurally lower than its centre cell, so using it as the denominator would inflate WFE and make the whole tab read optimistic.
  2. **A seam carries the incoming run's own position.**
     - When run k picks different parameters from run k−1, the first bar of run k's test window holds whatever run k's parameters say to hold — the series is cut, not reset.
     - That is what actually happens when you switch parameters; forcing every seam flat would invent n−1 exits nobody traded.
     - The switching cost is charged automatically (the stitched series changes weight at the seam and `precise_pnl` bills the fee).
     - Every per-run test number is sliced out of that ONE stitched series, never re-priced per run, so the run table's trade counts sum to the stitched total and its returns compound to the curve's end.
  3. **Warmup is applied to every training slice.** Signals are computed on the full history, but each training window's PnL skips that window's first `warmup` bars — otherwise run 1 trains on bars where the indicator has not warmed up and picks noise, and the runs would not be the same effective length. Test windows are not trimmed (already warm, and they must stay contiguous to stitch). This is also why no embargo is needed: the test window sits immediately after the training window it was picked from. **Pass the strategy's `WARMUP`.**
- **Guards** (all refuse rather than write something misleading): fewer than 3 runs raises and writes nothing (「資料只夠 K 輪」); more than 1000 runs raises (use a longer step); a run whose training Sharpe is ≤ 0 is marked failed — it stays in `runs[]` and in `excluded_runs`, but is left out of the in-sample average; an in-sample average below 0.25 writes `wfe: null` instead of dividing (a tiny or negative denominator inverts the diagnosis).
- **No MCPT, ever** — this tab shows no p-value, and `lib/validation.mcpt` permutes returns at a fixed position, which answers a different question. The p-value stays in the backtest tab.
- `wf.json` contract (shared with api/web — do NOT rename keys): `row_param`, `col_param`, `row_vals`, `col_vals`, `current` (the two constants as VALUES, or null), `lookback_days`, `step_days`, `n_runs`, `tail_days` (days at the end that were too few for one more run), `fee`, `start`, `end`, `oos {dates, cum}` (one point per calendar day; `cum` = cumulative return in **percent**), `oos_stats` / `is_stats` (the flat `'Sharpe Ratio'` / `'Ann. Return [%]'` / `'Max Drawdown [%]'` / `'Trades'` keys `lib/runner.py` already uses — `is_stats` values are the average over the runs that were NOT excluded, and are null when every run failed), `wfe` (number or null), `excluded_runs` (run numbers, 1-based), `runs[]` (`{k, train_start, train_end, test_start, test_end, params, train_sharpe, test_sharpe, test_return, trades}`; `params` are the axis values, `train_start` is post-warmup, `test_return` is that window's period return in percent, not annualized), `generated_at`.
  - The api validates the shape and drops the WHOLE block if anything fails — never hand-write this file.
- **Walk-forward workflow** — one `wf.py` in the strategy folder (never inside `strategy.py`): build the axes the same way `scan.py` does → `run_walk_forward` → report the numbers. It counts as ONE iteration under the Iteration Brakes, and it does **not** end with adopting parameters: the result is a verdict on "picking parameters from history", not a parameter set. - **Look-ahead check is automatic in every backtest (Type A and C).**
  - After `compute_signals`, `run()` cuts the data off at five points (one of them "drop the last bar"; a Type C also always gets up to two cuts just before a symbol's first priced bar — placed where the most symbols already have other data (fundamentals, revenue…) in the `fetch_data` output but no price yet — run first and, like "drop the last bar", regardless of the time budget; when `fetch_data` builds its columns from what `lib.data` returned, so the truncated run really lacks that symbol, a cross-sectional rank over not-yet-listed stocks is caught every time and the refusal lists the missing columns), re-runs `fetch_data` + `compute_signals` on each (the `lib.data` results `fetch_data` fetched are replayed truncated — no extra fetch, so indicators built in `_add_indicators` are covered) and compares every bar the two runs share, after `WARMUP`.
  - If a bar's position / weight changes when later bars are removed, the backtest is **refused**: stdout says `偷看未來 (look-ahead)`, names the cut, the first bar that moved and the matching lines of `strategy.py`, and no `stats.json`, version or chart is written.
  - Fix the cause (`shift(-n)`, `bfill`, `rolling(center=True)`, a mean/std/min/max/percentile/rank over the whole series, `resample(label='left')` joined back onto shorter bars, `merge_asof(direction='forward')`, the old Type C `_rebalance_mask` with `shift(-1)`) and re-run — never work around it.
  - A clean run prints `Look-ahead check: passed (…)`; on a Type C it also says the symbol-set cut dropped not-yet-listed symbols.
  - `⚠️ Look-ahead check passed with a gap` means the symbol-set check `did not take effect` (columns still there after truncation — e.g. the universe is reindexed to a fixed list) or `failed to run` (with the error): the other cuts agreed, but a rank over stocks not listed yet is NOT verified — tell the user so, exactly as for a skipped check; `Look-ahead check skipped` (nondeterministic strategy, data fetched outside `lib.data`, too few bars) means the backtest is NOT verified — say so when reporting it.
  - Recorded `lib.data` feeds listed in `FEED_TIMING` are cut by their **publication** time, so a daily feed joined onto intraday bars without `align_feed` is refused too; a feed outside `lib.data` (or one `FEED_TIMING` does not list) is cut by its stamps, which cannot reveal a publication lag.
  - Settlement bars (`txf_settlement_mask`, `settlement_signals_from_db`) are exempt from being the last bar of a cut.
- **Type C buy-and-hold benchmark (`benchmark_bh`) on a performance refresh**: when the refresh cannot fetch the benchmark's prices, `stats.json` keeps the last `benchmark_bh` stamped `as_of` (`YYYY-MM-DD`, the last day its figures reach) for up to 7 days past that date, then `null`. - **MCPT is automatic in every Type A backtest.**
  - `run()` calls `mcpt()` on the backtest's own close / position (`fee=FEE`, `periods_per_year` from the data's real date span — the same figure the Sharpe is annualized with — `vol_window` = one month of bars (`max(20, round(periods_per_year/12))`: 1h crypto → 730 ≈ the lib default 720, daily → 21; the manual daily-stock recipe below uses 60), `max_lev` / `target_vol` at lib defaults, permutations drawn from a private RNG seeded 42 so the same backtest always gives the same p-value without touching the global numpy seed) and writes three flat keys into `stats.json` next to the other stats: `"MCPT p-value"` (float), `"MCPT Permutations"` (int), `"MCPT Distribution"` (`{"edges": [31 floats], "counts": [30 ints], "actual": float}` — the permuted-Sharpe histogram the web draws; `actual` is the strategy's own MCPT Sharpe and may sit outside `edges`).
  - The backtest stdout shows `MCPT p-value: … (n=…)` — report it with the other stats.
  - Strategy constants: `MCPT_N = <int>` overrides the permutation count (default 2000, ≈ a few seconds on 40k bars); `MCPT = False` skips the test.
  - The count actually run is scaled to a runtime budget of 4e8 bars × permutations (`n_eff = min(MCPT_N, max(1000, 4e8 // bars))`, hard cap 20000): 200k bars (5min, 2 years) still get 2000, 1M bars (1min, 2 years) get 1000 — the 1000 floor holds however long the history is, so only an explicit `MCPT_N` below it produces a smaller count.
  - A reduction is logged as a warning naming both counts, and `"MCPT Permutations"` shows the effective n.
  - An `MCPT_N` below 1000 is never raised for you — it is the strategy's own choice — but the backtest prints its own stdout line under the `MCPT p-value:` line (and logs the same) saying that n would be rejected by the library listing gate: relay that to the user (raise `MCPT_N` and re-run, or leave it if the strategy is not headed for the library) rather than editing the number yourself.
  - If the histogram comes out unusable (edges collapsed) but the p-value is sound, p-value + permutations are written without the Distribution.
  - A strategy with 0 trades, too-short data or any mcpt failure just logs a warning and writes no MCPT key — never a failed backtest.
  - **Type C (portfolio) has no automatic MCPT** — `mcpt()` tests one price series against one position series, and collapsing a portfolio into one return series would be the forbidden bootstrap; don't fake one.
- **The parameter scan never runs MCPT** (`scan_grid` goes straight through `precise_pnl`; a scan is dozens to hundreds of backtests). Do not add it to `scan.py` or run it on the plateau — the adopt step's backtest produces the p-value.

- **Any *other* Monte Carlo / bootstrap has no lib function, and its numbers are only comparable within one calibration.**
  - `lib/validation.py` is MCPT and nothing else; a block-bootstrap worst-case drawdown, a path simulation, a scenario resample are each hand-written in the strategy's `validate.py`.
  - None of them is an MCPT substitute — they yield no p-value, and only a `run()`-based Type A backtest produces one — and the Type C ban above still holds: a portfolio may not be collapsed into one return series to bootstrap it.
  - **Report a percentile, not the extreme.**
  - The worst of N paths is an extreme that gets monotonically worse as `paths` grows, so two "worst drawdowns" drawn with different `paths` are not the same estimator — quote the 5th percentile and the median, and keep the extreme as a footnote.
  - Every such number, wherever it is written down (a note file, a report block, a reply to the user), carries next to it the **calibration fields**, which decide whether two numbers are comparable: signal version (the strategy file's date/mtime, or a revision you name in the note — the workspace is usually not a git repo, so do not count on a commit hash), symbol and data range (start–end), bar interval, resampling scheme (overlapping or not, with or without replacement, fixed or random block length) and block length in bars and the days they equal where applicable, simulated path length, `paths`, target vol and leverage cap, and fee — plus the **reproducibility field** `seed`, which does not affect comparability.
  - The script prints all of them with the number so the two cannot drift apart; a number found without its calibration is unusable — recover the calibration from the script that produced it, or rerun it, but never quote it.
  - Numbers from different calibrations measure different things: never treat them as the same figure — not as each other's baseline, not carried into another table, not mixed in one column.
  - A deliberate side-by-side is a sensitivity study: label it as one and vary a single calibration axis at a time (bar interval alone can move a worst-case drawdown by tens of percentage points).

  - Before anything is written the report goes to the platform's own validator (no copy of its rules here): refused → `ValueError` with the api's message naming the field, nothing written; fix it and call again with the same id. No verdict (no machine token, offline, timeout, an older api) → written unchecked, and a refusal at upload lands in `reports/upload_errors.log`. Checked locally: only the id (`[A-Za-z0-9_-]{1,64}`) and the image file names (plain names, not paths).
  - For `type="research"` it also prints advisory `WARNING:` lines (title wider than 80, where a CJK character counts 2; no `kpi_row` right after the lead — `references/reports.md` §7b).
  - They never stop the write
- `edit_report(report_id, title=None, change=None, images=None)` → path of the file written. Changes the one report the user named, where it is: same id, same `created_at`, same pictures; `change` is a function that edits the block list. Never edit the report JSON by hand, and never use it for a report nobody named or for 「再做一份」 (`references/reports.md` §1)
- Block types, field limits and the drop-directory contract: `references/reports.md`.

  - Two items still owe a real-account check (doc verification alone could not close them): OKX — send one internal transfer and confirm `type=4` really keeps it out of both history endpoints; BingX — after a deposit completes, confirm which status value it actually lands on (official reference says 1=Not credited while ccxt's executed mapping treats 1 as completed; the ccxt reading {1, 6} is what ships).

`lib/venue.py` — **chat-side venue bind.**
`bind(venue_id, env)` hands a key the user pasted in chat to the platform runtime's own `.env` writer (the one the web bind uses: flock, atomic 0600 write, other-venue eviction + halt, `manager/credentials.ui.json`), so the machine ends up exactly as after a web bind.

`lib/guard.py` — **kill switch + order audit log.** Enforced inside `lib/order_*.py`'s transport layer and again in `lib/portfolio.reconcile()` — no caller opts in, nothing to wire:
- If the file `state/HALT` exists, EVERY order raises `guard.Halted` before any network call — entries, reduce-only closes, SL/TP (a full freeze: a paused machine sends nothing; orders already resting on the exchange are left alone). Cancels and leverage changes still pass. The file's existence is authoritative — malformed content still halts.
- Closing while paused is the user's explicit close only: `manager/flatten.py` (暫停並關閉部位) and `manager/close_symbol.py` take the close pass (`guard.grant_halt_closes`), and a close-all leg the reconciler finishes for flatten runs inside `guard.halt_close_pass`. Reduces only — never call either from a strategy or an ad-hoc script.
- Pause between `open_position`'s fill and its SL/TP (Binance, OKX, Gate.io place them as a second step; Bybit and BingX attach them to the entry): the SL/TP is refused like any order, and `open_position` raises `ProtectionFailed` caused by `guard.Halted`. The position is open with NO stop until the user presses 啟動下單, and nothing re-places it on its own — catch it, tell the user now, and once the halt is cleared re-place with `place_protective_orders`. Called on its own under HALT (Binance, OKX, Gate.io, BingX), `place_protective_orders` raises the same `ProtectionFailed`; the message names only the order(s) not placed and says which went out before the pause.
- A Type B script or monitor that moves a resting stop by cancel + re-place must check `guard.halted()` (and `guard.restart_stopped()`) before the cancel: under HALT the cancel passes and the new stop is refused, which leaves the position with no stop at all.
- **Per-strategy halt (monitor-only)** — `halt_path_for(strategy)` → `state/HALT_<strategy>`; `halted_for(strategy)` → True if the global HALT OR that file exists (never False under the global HALT); `halt_info_for(strategy)` → attribution dict or None (global wins; unreadable file still halts); `trip_halt_for(strategy, reason, source)` writes it atomically and audits `halt_tripped` with `scope`; `clear_halt_for(strategy, source)` removes it (only on explicit user request).
  - Use it for a strategy's own circuit breaker instead of the global HALT, which freezes every strategy.
  - **`lib/order_*` and the reconciler never read it** — a strategy or monitor must call `halted_for` itself before opening exposure.
  - `manager/stop_strategy.py` trips it for the stopped strategy.
- `reconcile()` denies every leg itself while halted, before calling `place_order_fn`. That is the layer that covers a reconciler whose exchange has no official `lib/order_*.py` and whose `place_order` was hand-written — the transport-layer check alone would miss it. Denials are audited and logged, but deliberately NOT sent to Telegram: the user tripped the halt to stop the noise.
- `trip_halt(reason, source)` — set it (user says 停 / healthcheck anomaly). `clear_halt(source)` — **only on explicit user instruction; NEVER clear a halt on your own initiative.** `halted()` / `halt_info()` — check state.
- Every order attempt / outcome / denial is appended to `state/audit.jsonl` (fsynced). When the user asks "你到底下了什麼單", read this file — it is the record of what was actually sent, not what was intended.

`lib/order_paper.py` — **Paper (simulated) venue — no exchange, no keys. Ships implemented; same surface as the other order libs (four reconciler names, limit layer, spot layer, `open_position`/`place_protective_orders`, `lib/guard` built in), so the reconciler / dispatch / flatten / web run unchanged.** What is simulated (full list in the module docstring):
- **Price = the market's latest real (unadjusted) price** (`lib/paper_data.current_price`, 30 s process cache), never the strategy's own `fetch_data` bar and never a dividend/split-adjusted close:
  - crypto (any `…USDT` / `…USDC`, stock perps like `NVDAUSDT` included): Binance USDT-M last trade (`/fapi/v1/ticker/price`, no key — the market `fetch_kline` reads). Spot rows price off the perp. Binance unreachable → the latest closed 1m bar via Blave `/kline` when there is a Blave key (Binance is then skipped for 60 s in that process); last resort — a coin Binance USDT-M does not list (OKX / BingX only), or a key-less desktop where Binance is blocked — the owning strategy's own `fetch_data` latest Close (a `[paper_data]` warning line says so); no owner either → no price. A Binance price — the ticker or the Blave 1m bar standing in for it — more than 10× off (either way) the owning strategy's own latest Close is a different instrument under the same ticker (Binance `CATUSDT` is Caterpillar, not the CAT memecoin): the strategy's own Close is used and a `[paper_data]` warning says so; an owner close that cannot be read keeps Binance's price. The verdict is made once per symbol and owner per UTC day (`state/paper_crypto_collision.json`), so a symbol judged clean does not run its owner's `fetch_data` again that day; an unreadable owner close (or one that is NaN or ≤ 0) is retried after 10 minutes and keeps Binance's price meanwhile; once a symbol is judged a collision, an unreadable owner close means no price that read (an entry is refused, a holding marks at its entry), never Binance's. A real move of more than 10× inside the owner's last bar is judged a collision too.
  - TAIFEX futures (TXF/MXF/TMF, stock futures): the latest 1m Close of the continuous near-month series (`fetch_twfutures_ohlcv`'s series, read uncached; MXF/TMF price off TXF). Same series and roll as the strategies; a closed market answers its last minute. No Blave data access on the desktop → TAIFEX's own daily close (TXF family only).
  - TW stocks: the unadjusted daily close (below).
  - US stocks (a symbol a strategy reads with `fetch_usstock_price`): Yahoo's latest final unadjusted daily close (the previous session's close). A paper order placed by hand in chat fills at it; lib.data refuses Yahoo on every live tick, so an automatic US paper order is refused.
  - anything else (`fetch_db_kline` CME/ICE futures): the owning strategy's `fetch_data`, latest Close.
  - Nothing priced → `PaperNoPrice`: an entry is refused (never a made-up price); a close falls back to the row's entry. Paper fills therefore differ from the backtest by the tick-vs-bar timing (it fills now, the backtest at the next bar's open) and, on stocks, by dividends (below).
  - **TW stocks: every TW stock code fills and marks at its UNADJUSTED daily close** (`fetch_twstock_price`, Blave CDN on the desktop) — Type A, Type C component or anything else, never the strategy's `fetch_twstock_price_adj`. A symbol an intraday Type A trades (`INTERVAL` under 1d) fills and marks at that strategy's latest unadjusted bar instead (`fetch_twstock_ohlcv(…, adjust=False)` on the longest schema dividing the interval: 1h/4h → 60m) — the bar the page sizes its shares with; that bar unreadable (it needs Blave data) → the previous daily close, and the fill carries `price_note`. It is the price a broker app shows and the one the portfolio page turns TWD into shares with, so the shares the page lists are the shares paper buys (a dividend-adjusted close carries every factor since the stock's first day on its source and would size fewer shares). A Type C `fetch_data` is never run for a price (a whole TW universe takes minutes). A stock suspended for more than 14 days is priced at its last close up to 400 days back, so its close-out still goes. **Dividends are not booked on paper**: on an ex-dividend / ex-rights date the unadjusted close drops and paper equity drops with it — no cash dividend is credited, no stock-dividend shares are added — so a paper TW stock trails its dividend-adjusted backtest by roughly the yield. The drop sends no order (the own-positions book diffs fill-time cost, not the mark). Say so when a user compares paper with the backtest. A paper TW row booked before this switch (valued at the adjusted close) is restated once at the first read after the update — a position's entry × raw/adjusted, a share holding's (adjusted − raw) × shares back in cash, audited as `paper_tw_rebase` — so the switch is neither an equity drop nor a realized loss; no order, no fill.
- **Fills are IMMEDIATE at that price, no bid/ask** (the live-paper convention, e.g. Freqtrade dry-run; beginner-tier fidelity — Webull/TradingView do the same). **The fee is the backtest's**: every fill (market, crossing or resting limit, SL/TP) pays one per-side rate — the `FEE` of the strategy in the 下單設定 trading that symbol on that market (several → the highest), else its market default, which already includes slippage; a market with neither keeps paper's fixed rates (`references/trading-costs.md` › *Where the rate is used*). Resting limits fill at their OWN limit price when the mark crosses it; post-only crossing → `{'status': 'post_only_rejected'}`; resting orders + SL/TP settle **lazily on every call into the lib** (any get_* / account read)
- **TW stocks trade only in the TWSE session** (09:00–13:30 Taipei on a trading day, `lib/paper_data.tw_session_open`; the holiday table needs a Blave API plan — without one, or with the api unreachable, the weekday alone decides, and a typhoon closure reaches the table only that evening or the next morning; the day's verdict is kept in `state/paper_tw_day.json`, a failed lookup retried at most every 10 minutes). Outside it every TW stock order is refused as at the exchange — closes, SL/TP triggers and close-all included (`PaperMarketClosed`): the reconciler holds every paper TW stock key as is (`last_reconcile.json` lists them under `market_closed`), so a daily strategy's after-close signal fills at the next session's first round, at the latest close; close-all (暫停並全部平倉) books those keys in `state/paper_tw_close.json` and the reconciler closes them in its first round after the open while HALT holds — even a key the signal gate (「等新訊號」) or an unreadable strategy would otherwise hold; pressing 啟動下單 first (either start: catch up or wait for a new signal) cancels it — the report lists the pending keys as `deferred_close` and the start box names them before the user confirms; when the machine restarted in between (the runtime stamps `restart_at` on the file), the order-error line says the start came after a restart. After a machine restart (stopped, `state/reconciler_stopped.json`) nothing is deferred — no round would run — and the page tells the user to press close-all again in the session. **Whole shares only**, floored — and the reconcile gate for a paper TW stock is in TWD: the 10 USD floor × the rate, or 1.05 shares when larger (`lib.execute._paper_tw_sizes`) — for entries and partial reduces alike (`_paper_tw_reduce_gate`; a whole-position close keeps its own gate) — so a gap under one share is left alone instead of re-sent every round (a sub-share order sends nothing; a full close takes a legacy fractional row whole). **A TW stock on paper is always held as cash shares** — its key is `SYMBOL@spot` whatever `MARKET` says (the buy pays the full price from cash, no leverage). **No TW stock shorts on paper**: a short signal counts as flat in the target (it does not cancel another strategy's long), a direct short from flat raises `PaperError`, and a sell past the long only closes it
- **One USD account**: a crypto notional position needs no FX (qty = USD ÷ price, so PnL = notional × return, unitless). A **TW stock** is TWD-priced: its amount is TWD, qty = TWD ÷ price is shares, so its PnL and fee are TWD and are booked ÷ the USD rate exactly like contract money below — on the swap path and on the spot path (`MARKET = "spot"`: the code itself is the inventory, `2330@spot`; cost and proceeds ÷ rate). A **contract position** (TXF/MXF/TMF lots; later TW shares) is money in the contract's currency (lots × point value × Δindex = TWD), so its realized PnL and fee are booked ÷ the USD rate at the fill, and its open PnL and margin ÷ the current rate (`lib/paper_data.usd_rate`, the platform's own rate table cached in `state/paper_fx.json`). Per-position `unrealized_pnl` / `margin` from `account_paper.get_positions` stay in TWD on lot rows and TW stock rows; only equity (and holdings' `usdt_value`) is USD. A TWD entry with no rate available is refused. Permissive rules (a price feed is not an instrument spec — no min-qty/notional/step gating; the reconciler's slice threshold is the floor). Reduce-only caps at the position, never flips, and is NEVER refused; gross notional capped at 10× equity on exposure-adding fills; a position whose price source vanishes marks at entry (never bricks the account) and stays closeable
- Ledger `state/paper_ledger.json` (atomic writes + flock / msvcrt; `PAPER_INITIAL_EQUITY` in `.env` seeds it, default 100,000 USDT for a ledger created from now on — an existing ledger keeps its own `initial_cash`; the web writes `PAPER_BOUND_TS` on every bind and a ledger older than the bind is re-seeded, so unbind→rebind is a fresh 100,000);
  - reduce/close legs are never refused by the equity/leverage checks (only exposure-adding fills are);
  - `reset_account(env, cash=None)` wipes and re-seeds — **explicit user request only**;
  - client_order_id is idempotent (resend → the earlier fill), HALT blocks every order (closes only inside the user's explicit close), every attempt lands in `state/audit.jsonl` with `venue: paper`

`lib/order_bybit.py` — **Bybit order execution (USDT linear perp + spot, UTA). Ships implemented — NEVER hand-write Bybit order calls; import from here.** Same contract and surface as the other order libs. Bybit facts, measured live 2026-09-09:
- **SL/TP are native and ATOMIC** — `takeProfit`/`stopLoss`/`tpslMode:"Full"` ride on `/v5/order/create` itself, so `open_position(sl_price=, tp_price=)` leaves no naked window. A flat position auto-cancels them
- **A price formatted as `"0"` is accepted silently and means NO protection** — `float()`-ing a tick of `0.00001` stringifies as `1e-05`, whose decimal count reads as zero; the lib formats every price from the filter's ORIGINAL string via `Decimal`, and `open_position` reads the position back and raises `ProtectionFailed` if protection is missing
- `get_open_orders` **drops rows with a non-empty `stopOrderType`** — Bybit lists the position's own SL/TP as open orders, and an orphan sweep would strip the protection
- `get_open_algo_orders(env, symbol)` returns exactly those conditional rows (read-only, for close checks); `cancel_all_orders(env, symbol)` (`/v5/order/cancel-all`, no `orderFilter`) cancels every kind incl. TP/SL and trailing — only when also closing the position
- **`orderLinkId` dedup is PERMANENT**, not just the unfilled window (a resend after fill returns 110072) — unlike Binance/OKX, a blind resubmit cannot double the position, so connection-error retries carrying an orderLinkId are safe and resolve back to the original order
- **Hedge mode hard-rejects an order with no `positionIdx`** (10001). Position mode is read fresh on every order, never cached — the user can flip it in the app mid-session
- post-only that would cross is ACCEPTED then auto-cancelled with `rejectReason EC_PostOnlyWillTakeLiquidity` (OKX-style, not an error code) → mapped to `{'status': 'post_only_rejected'}`; `PartiallyFilledCanceled` is normalized to `canceled` in-lib (it is terminal but reads like an open partial)
- cancel of an already-gone or never-existing order is retCode 110001 → returns `{'status': 'order_not_found'}` instead of raising
- Market orders split across several fills — the aggregate on the order row (`cumExecQty`/`avgPrice`/`cumExecFee`) is the answer, never one fill
- **Spot layer**: BUYs sized in QUOTE (`marketUnit:"quoteCoin"`, USD straight in), SELLs in base floored to `basePrecision` (spot filters are a different shape from linear — `basePrecision` not `qtyStep`, `minOrderAmt` not `minNotionalValue`). **The buy fee is charged in the BASE coin** (a 6 USDT buy reporting `cumExecQty` 66.3 credits 66.2337), so size sells from the WALLET, not from the buy's `cumExecQty`. Both sides gate on `minOrderAmt` (retCode 170140 below it). Guard: buy = entry, sell = reduce — under HALT both are refused (the freeze: no order of any kind); a sell goes out only inside the user's explicit close (`manager/flatten.py` / `manager/close_symbol.py`)
- Symbols are already canonical (`BTCUSDT`), qty is base units, `contract_value` is 1 — no ctVal conversion anywhere
- `BYBIT_DEMO=true` routes to Bybit Demo Trading — see *Demo / testnet flags* below

`lib/order_stockcoin.py` — **StockCoin order execution (USDT perps on US / KR stocks, ETFs, commodities, pre-IPO names, a few coins). Ships implemented — NEVER hand-write StockCoin order calls; import from here.** Market, limit (chase / TWAP) and SL/TP layers; no spot. Facts measured on a live key:
- Symbols: the venue's `NVDA-PERP-USDT` ↔ canonical `NVDAUSDT` (`lib.data.normalize_symbol` takes the `-PERP-` form). Size is CONTRACTS of 0.0001 base each; the lib converts base qty itself and refuses a symbol whose 24h turnover contradicts that multiplier. One contract is the minimum.
- **Not every listed contract is open to the API**: a one-contract open + close filled on 31 of 36; BTC, ETH, XRP, SAMSUNG and SKHYNIX answer -1157, raised as `symbol_unavailable` with a Chinese reason. Which ones are open is the venue's call — read it off the reply, don't keep a list.
- An order past the account's margin answers -1131 "Balance insufficient" → `insufficient_margin` (measured). Equity = `total` + `totalUnRealizedPnl` = the row's `futureAssetTotal` (measured with a position open; `total` alone does not move with the price).
- Hedge mode only: the side names the leg (`BUY_OPEN` / `SELL_CLOSE` long, `SELL_OPEN` / `BUY_CLOSE` short), so a close can never open the other side; a close is capped at the leg's `available` contracts.
- Market order = `orderType LIMIT` + `priceType MARKET` + `price "0"`; `clientOrderId` is mandatory and a reused one answers -1141 (resolved back to the original order).
- Fees live on `/futures/trades`, not the order; rows can lag the fill (re-read briefly, else `commission` is None — never 0).
- **Post-only = `timeInForce LIMIT_MAKER`** (not in the venue doc); one that would cross answers -1158 → `{'status': 'post_only_rejected'}`. No tick size is published: the price is cut to the decimals the public book uses, and a -1134 ("decimal too long") steps down one decimal once. A cancel's reply is the order BEFORE the cancel, so `cancel_order` returns `cancel_accepted` unless that reply is already terminal — the chase confirms through `get_order`.
- **SL/TP are STOP orders** (`orderType STOP` + `triggerPrice`, market at the trigger, `*_CLOSE` side), placed by `place_protective_orders` / `open_position(sl_price=, tp_price=)` and verified in the open STOP list; listed by `get_open_algo_orders`, cancelled with `cancel_protective_orders` (`orderType=STOP`). Two-step (one round trip naked after the entry).
- **The venue does NOT cancel a position's stops when the position closes** (measured: the STOP was still listed after a market close). Left there, it would act on the next position opened on that leg. The lib cancels them in two places:
  - a close through this lib (market, or a chase limit seen filled through `get_order`) that leaves the leg at zero cancels that leg's STOP orders right away and reports them as `stops_cancel` on the result;
  - every reconcile round (`sweep_orphan_stops`, run from `lib.venue_wiring.auto_get_positions`) cancels the STOP orders of any leg that holds nothing — this is what clears a take-profit left behind after its stop-loss fired on the venue (and the reverse), which no lib call sees. A Type B script that runs without the reconciler must call `cancel_protective_orders` itself once its position is gone.
  - Zero is read twice before anything is cancelled; entry STOPs (`*_OPEN`) are never touched. A failed cancel is logged, audited (`stops_cancel_failed`), written as an order error and sent to the user (once per cooldown) — the close itself stands. `manager/close_symbol.py` cancels all LIMIT + STOP orders of the symbol as well.
- **A partial close does not resize the stops**: there is no close-whole-position flag, a stop covers the contracts it was placed for. After reducing, a stop for the old size can close more than is held — cancel and re-place it at the new size (`cancel_protective_orders` then `place_protective_orders`).
- No broker attribution exists for this venue.

**Clock skew** — every official order and account lib answers its venue's timestamp rejection (Binance -1021, Bybit 10002, OKX 50102, Gate.io REQUEST_EXPIRED, BingX 100421) by reading the venue's public server time, re-signing with that offset and retrying once; a second rejection raises. - Then import it in the strategy

Skill examples show data-fetch patterns only — integrate them into TEMPLATE_A.py using lib/ imports.

**Marketplace lib rule** — strategies shared via marketplace must follow this boundary strictly:
- `compute_signal`, indicator calculation, and all logic that affects trade decisions MUST stay in the strategy file — never in a custom lib
- Custom `lib/` files must only contain IO utilities (exchange order helpers, data fetchers) — logic that can be fully described by interface + behavior, not by implementation detail
- This allows recipients to reconstruct missing custom lib from the description without risking strategy inconsistency
