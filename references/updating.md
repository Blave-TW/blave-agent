# Updating the Workspace

Trigger: user says 更新 blaveclaw / 更新 blave agent / 更新系統 / 更新 config / update blaveclaw / update blave agent / update workspace — no link required.

## 0. Desktop app — stop here

If this workspace runs inside the Blave desktop app (the runtime's local mode; the workspace lives under the user's home, e.g. `~/Blave/workspace`, not `/opt/blave-agent`), **do not run this procedure**. On the desktop the framework ships with the app as one versioned bundle: the app updates itself, and on the next launch it refreshes the official files in this workspace (anything it overwrites that differed is backed up under `.official-backup/`). Do not clone the repo, do not merge `lib/`, and do not edit `VERSION` — a workspace `VERSION` newer than the app's makes the app skip its own refresh and leaves a new `lib/` running under an old runtime.

The two sides update differently:
- **This computer** — the app. 「立即更新到最新版本」 ("Update to the latest version now") at the top right of the chat input, or the Update button under Settings › General › About; this computer installs the new app version when it restarts.
- **The cloud machine** (only if the user has one) — **you, over the `blave` MCP, following `references/cloud-handoff.md` › *Updating the cloud machine* exactly**, and only when the user's own message in this conversation asks to update the cloud machine (typed, or the fixed message the app's Update button sends) — plus the user's own yes when that section asks before restarting the order program. Never send the user to the website to update it (the one exception: a machine with no `AGENTS.md` — `references/cloud-handoff.md` › NEVER, the read-`AGENTS.md`-first rule), and never send anything that makes the cloud machine's own agent start a turn (no message to it, no 「更新」 in its chat) — a cloud agent turn charges the user's cloud AI credit.

When the user says 更新 / update, reply with **which version each side is on**: this computer's workspace `VERSION`; the cloud machine's is shown next to it under Settings › General › About — point there; do not open an SSH session just to read it. A bare 更新 / update is not an ask to update the cloud machine: say where this computer's button is, and ask whether to update the cloud machine too. Outside that procedure you write nothing to the cloud machine's `lib/`, `manager/` or `VERSION`.

Everything below is for cloud machines only.

## 1. Skill

Nothing to install — the platform re-clones the blave-quant skill into `skills/blave-quant` once a day (a systemd timer / scheduled task on Blave Agent machines, a crontab entry on older openclaw boxes). Just check that `skills/blave-quant/SKILL.md` is there; if it is missing, say so in the report and stop — a hand-install would put it somewhere the daily job then overwrites.

## 2. Config

Clone https://github.com/Blave-TW/blave-agent to `/tmp/oc-config` as **reference only** — never as the live workspace — as a blobless clone with full history: `git clone --filter=blob:none https://github.com/Blave-TW/blave-agent /tmp/oc-config` (never `--depth`; the check below needs every past official version of each file). Run the clone in the foreground with an explicit long timeout (e.g. 300000ms) — never `run_in_background`: on a slow/throttled machine the clone can exceed the 120s default and auto-background, and the runtime kills backgrounded processes at turn end with no completion notification, silently dying instead of finishing. Then follow the "Updating an existing workspace" section of its `README.md` exactly: compare file by file; a file that already matches the clone is left alone.

**Nothing is merged — every official file is replaced whole, with a backup.** An official file is one whose exact path exists in the reference clone, under `lib/`, `manager/`, `references/`, `examples/` or `allocators/`, plus `AGENTS.md`, `CLAUDE.md`, `strategies/TEMPLATE_A.py` and `strategies/TEMPLATE_C.py`. This covers the backtest-chain libs (`lib/runner.py`, `lib/param_scan.py`, `lib/walk_forward.py`, `lib/validation.py`, `lib/analysis.py`), `lib/data.py`, the official broker libs (`lib/order_*.py` / `lib/account_*.py` / `lib/capital_worker.py` whose exact name is in the clone) and `references/` alike. Never combine the two versions by hand — an order lib stitched together by hand is order code nobody reviewed.

**Old version or changed here?** For each official file that differs from the clone (compare `AGENTS.md`, `CLAUDE.md` and the two templates with `cmp`, the five directories with `diff -rq`): if `git hash-object lib/data.py` appears in `git -C /tmp/oc-config log --format= --raw --no-abbrev -- lib/data.py` (either hash column of any line), it is just an older official version — replace it. Renames are not followed, nor a version that exists only in a two-parent commit, so this asks more often than strictly needed — that is expected. If it appears nowhere, it was **changed on this machine**: list those files and **ask before writing anything, whether or not the reconciler is running**: 「這幾個官方檔在這台主機上被改過:<檔名>。更新會把它們換成官方版(改過的那份會備份到 `.official-backup/`),要更新嗎?」 — and wait for the user's own yes in their next message. No promise that strategies are unaffected: a strategy runs the new `lib/` from its next run. If the user keeps those files, they are not touched and are reported as "not updated", the rest is updated, and `VERSION` is not copied.

**Backup, the desktop app's way:** one folder per update, `.official-backup/<old VERSION>-<UTC time>/` (`date -u +%Y%m%dT%H%M%SZ`; `<old VERSION>` must match `^[A-Za-z0-9._-]{1,40}$`, otherwise use `unknown`, and the time must match `^[0-9]{8}T[0-9]{6}Z$`, otherwise stop), which must not exist yet (`mkdir -p .official-backup`, then a plain `mkdir` of the tag folder; if it exists, stop). Every existing file that differs from the clone is copied there under its own relative path before it is replaced (`mkdir -p .official-backup/<tag>/lib`, `cp lib/data.py .official-backup/<tag>/lib/data.py`). **If a backup `cp` fails, or `cmp` of the backup against the original is not silent, do not replace that file** — stop and report which file and why. Older backup folders are never touched. List the folder and its files in the report.

**Atomic replace:** `cp /tmp/oc-config/lib/data.py lib/data.py.update-tmp`, then `mv lib/data.py.update-tmp lib/data.py` — a strategy starting at that moment never imports half a file. A whole directory that exists only in the clone is copied as one (`cp -R` to `<dir>.update-tmp`, then `mv`). Check each written file with `cmp` against the clone.

**If a write is refused.** If a write onto an official file is refused, do not route around it — no script, no `python3`, no other command: leave it, report it as "not updated", and do not copy `VERSION`. Tell the user which files could not be replaced and that this machine still runs the old version of them.

**Official files missing locally are copied in**, from those five directories only — nothing else in the clone (`shell/`, `tests/`, `runtime/`, `patches/`, top-level scripts) is copied. **`lib/venue_errors.py` must always be copied when it is missing locally** — the official `account_*.py` libs and `manager/reconciler.py` import it (the account libs degrade without it; the reconciler cannot start).

**Never touched:** any file whose path is not in the reference clone — the user's own `lib/order_*.py` / `lib/account_*.py` exchange integration and any other lib they added — plus `control/`, `state/`, `.env`, `manager/portfolio_config.json` and the user's strategies. The filename alone doesn't tell you if an `order_*` / `account_*` file is user-created; its presence in the clone does.

**Restart the reconciler when the update touched `lib/` or `manager/` — REQUIRED, same session, before telling the user anything is enabled** (why: `references/manager.md` › *Workspace update ⇒ reconciler restart*). A running reconciler keeps executing the code it started with — including its in-memory HALT state — until it restarts; skipping this step leaves every fix in the update inactive on the one process that places orders.
- **Restart only a reconciler that is already running.** `systemctl restart` and `nssm start` also START a stopped one, and a stopped reconciler means the user has not started trading (or deliberately stopped it) — starting it for them crosses the deployment redline in `AGENTS.md`. Not running → leave it stopped and say so in the report.
- **If `state/reconciler_stopped.json` exists, restart it all the same** (still only a running one) — provided the updated `manager/reconciler.py` contains `RESTART_STOP_PATH`: that reconciler reads the file and skips every round, so the restart sends no order, and it replaces an old program that ignored the file. If `manager/reconciler.py` does not contain it (not updated), do not restart; that is not a failed restart — `VERSION` is still copied. Either way the machine stays paused: tell the user 「自動下單仍暫停，而且更新後連平倉與停損都不會執行；按「啟動下單」才會繼續，要先平倉請到交易所操作。」 / "Auto-trading is still paused, and after the update exits and stops won't run either. Press Start Trading to resume, or close positions at the exchange first." Trading stays stopped until the user presses 啟動下單 (Start trading) on the Auto trading page.
- **How:** follow `references/manager.md` › *Linux — check for the systemd unit FIRST, tmux only as fallback* / *Windows — NSSM service*. In short: Linux with the unit `active` → `sudo -n systemctl restart blave-agent-reconciler.service`; Linux without the unit file and `tmux has-session -t reconciler` succeeding → kill that session and start it again exactly as manager.md shows; Windows with `nssm status blaveclaw-reconciler` reporting `SERVICE_RUNNING` → `nssm restart blaveclaw-reconciler`. Never start a tmux session on a machine where the systemd unit is active.
- **Verify** it is running again (`systemctl is-active …` / `tmux has-session …` / `nssm status …`) before reporting. If the restart failed, report exactly that — the update is on disk but the old code is still trading — never "updated and active" — and do not copy `VERSION`.

Last — after the reconciler step below — copy the reference clone's `VERSION` file to the workspace root verbatim, and only if every step above succeeded and no official file was left on an older version, and (when the reconciler was restarted) only after it is verified running again — the machine reports it to the platform and it drives the web workspace's "update available" indicator. A restart that failed leaves `VERSION` old, so the update is offered again.

Remove `/tmp/oc-config` when done.

Report exactly what changed (or that everything was already up to date) — don't claim "updated" without checking.
